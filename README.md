# ReplyMind

An Android auto-reply app that classifies every incoming WhatsApp / Telegram /
Messenger message by intent and routes it to the right reply — urgent stays
loud, spam stays silent, casual chat gets a warm auto-reply. Replies are
generated by a self-hosted FastAPI backend that runs entirely on the user's
own laptop. No subscription, no third-party server in the loop unless the
user opts into a BYOK LLM provider.

This is a final-year academic project. It is **not published** to any app
store and there are no donation links, telemetry, or analytics.

## What's in the box

```
+--------------------+        +-------------------------+
|  Android (Kotlin)  |        |   Backend (Python)      |
|  ReplyMind app     |        |   FastAPI + PyTorch     |
|                    |        |                         |
|  NotificationListener      POST /classify             |
|        │           |        |        │                |
|        ▼           |  HTTP  |        ▼                |
|  3-tier cascade    | -----> |  Embedder (MiniLM)      |
|   1. Backend       |        |  Per-user RAG (Chroma)  |
|   2. BYOK LLM      |        |  MLP head (384→256→6)   |
|   3. Template      |        |  → category + reply     |
|        │           |        |                         |
|        ▼           |        |                         |
|  Per-category      |        |  SQLite audit log       |
|  routing & reply   |        |                         |
+--------------------+        +-------------------------+
```

The classifier picks one of six categories per message: **urgent, work,
family & friends, promotional, spam, other**. Each category has a default
action (escalate, reply with template, suppress, etc.) and a per-user
reply template that can be overridden.

## Features

- Six-way intent classifier (sentence-transformer + 2-layer MLP) — ~92%
  accuracy on a held-out test set built from five public corpora.
- Per-user retrieval-augmented context: every classified message is
  remembered, so future replies improve with use.
- Confidence-gated semantic backstop: when the classifier is unsure, it
  falls back to cosine-matching against plain-English category descriptions.
- Layered, graceful fallback: backend → BYOK LLM → template. A single tier
  failing never blocks the auto-reply.
- BYOK support for OpenAI / Groq / OpenRouter / Anthropic / custom URLs.
- Local-first: backend runs on the user's laptop; message bodies never leave
  the user's network (unless the BYOK path is enabled, explicitly).
- Encrypted at rest on Android: bearer token, user profile, and BYOK key all
  live in `EncryptedSharedPreferences` (Keystore-backed AES-GCM).

## Quick start

### 1. Backend

```bash
cd backend
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                 # set DEMO_TOKEN and BACKEND_URL
python -m backend.data.build         # downloads + stitches the public datasets
python -m backend.train              # trains models/classifier.pt (~10 min on CPU)
python -m backend.eval               # writes models/eval_report.json
uvicorn backend.main:app --host 0.0.0.0 --port 8765
```

Quick health check:

```bash
curl -H "Authorization: Bearer $(grep DEMO_TOKEN backend/.env | cut -d= -f2)" \
     http://127.0.0.1:8765/healthz
# {"ok":true,"model_loaded":true,"chroma_ready":true}
```

### 2. Android client

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
./gradlew assembleDefaultDebug
adb install -r app/build/outputs/apk/Default/debug/app-Default-debug.apk
```

The URL and bearer token are baked into `BuildConfig` from `backend/.env` at
build time — no in-app configuration needed.

### 3. Connecting the phone

On the emulator the backend is automatically reachable at `http://10.0.2.2:8765`.

For a physical device over USB, forward the port:

```bash
adb -s <device-serial> reverse tcp:8765 tcp:8765
```

`localhost:8765` on the phone now maps to `127.0.0.1:8765` on the laptop.
The cleartext-traffic allowlist in `network_security_config.xml` permits
exactly these three hosts: `127.0.0.1`, `10.0.2.2`, `localhost`.

## Privacy and security

- Backend listens on `0.0.0.0` but only `127.0.0.1` / `10.0.2.2` are reachable
  from the app via the cleartext-traffic allowlist.
- Bearer token, user profile, and BYOK API key are stored in
  `EncryptedSharedPreferences` on the device.
- Per-user vector stores are namespaced by a device-generated UUID; the
  audit-log table is scoped per `user_id` server-side.
- `promotional` and `spam` categories default to **SUPPRESS** (no reply),
  which catches OTPs and verification codes by construction.
- Snippet retention (storing the inbound message body in the Inbox audit log)
  is a user-controlled preference.

See [`PRIVACY.md`](PRIVACY.md) for the full statement.
